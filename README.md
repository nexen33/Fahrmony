# Fahrmony 合拍

![Platform](https://img.shields.io/badge/Platform-Android%20Auto%20%7C%20Android-green)

> 一个为 Android Auto 打造的本地互操作桥接工具，让海外行车使用 Android Auto 时能够自然显示和部分操控你常用的中文流媒体音频与即时通讯通知。

## 什么是 Fahrmony？

**Fahrmony** 取名自德语驾驶（**Fahren**）与英文和鸣（**Harmony**），中文译为“**合拍**”。

很多生活在海外的华人朋友在驾驶支持 Android Auto 的车辆时，常面临一个很无奈的现实痛点：车机原生应用生态里几乎找不到大家习惯使用的中文软件。手机里放着常听的音乐软件或播客，上了车却往往只能退回最原始的蓝牙音频：车机中控和方向盘无法切歌、调控进度；行车途中微信、飞书等通讯软件收到新消息时，又不得不冒险掏出手机低头查看。

**Fahrmony 正是为化解这层隔阂而生**。它无需获取Root，不修改操作系统，纯粹依托安卓标准系统能力充当轻量级车载中间件，将手机后台已安装的音频播放状态投射到车机全屏与分屏控件上，并将重要即时消息以符合驾驶安全规范的语音朗读形式播报出来，让海外行车更加从容。

### 明确 Fahrmony 不是什么

为了避免产生误解，在使用前请知悉：
- **它不是独立的音乐播放器**：软件不内置任何音频解码器，不提供在线音乐播放与曲库服务。
- **它不替换原始应用**：手机上的音乐与通讯软件依然保留原样，账号登录、会员权益、私密曲库与真实音频流依然全部由原应用在底层负责。
- **它不托管、不代理、不缓存媒体文件**：软件内绝无任何音频下载或云端中转。
- **它不需要 Root 提权**：完全运行于安卓官方开放的沙盒安全边界之内。
- **它不破解任何第三方私有协议**：完全不包含针对任何商业软件的私有接口逆向工程或封包篡改。

## 工作原理

Fahrmony 基于安卓开放标准接口构建双向桥接链路：

1. **音频媒体链路**：通过通知监听服务与媒体会话管理器，实时捕获手机端正在发声的媒体，将其状态双向映射至车载媒体浏览服务中，直接通过车机中控和方向盘调控。
2. **通讯消息链路**：借助系统通知监听能力抓取消息通知，将其智能解构并清洗，转译为车载原生规范的卡片结构，触发车机安全语音朗读。
3. **独立进程隔离**：所有车载服务与底层监听逻辑常驻于独立的车载原生系统进程（`:car`）中，与手机前端界面进程完全物理隔离，通过高效的双向通信通道保持同步。

## 核心功能

- **标准车载媒体播控**：在车机屏幕上顺畅进行播放、暂停、上一曲、下一曲切换以及播放进度拖拽。
- **媒体会话发现与智能仲裁**：自动感知系统中正在发声的播放器，多应用切换时根据真实播放状态精准锚定焦点，杜绝车机卡片混乱漂移。
- **冷启动唤醒与热重连续播**：针对 App 与 Android Auto 冷启动与热重连进行了深度打磨。进入车机连接 Android Auto 时，系统自动感知并尝试恢复上次的播放状态，在绝大多数日常用车场景下无需驾驶员在手机或车机上手动点按播放；针对后台应用冷启动时的短暂无响应内置重试与自愈唤起机制。
- **自适应流光背景**：内置高对比度流光封面生成能力，彻底解决暗色专辑图和离线播放时导致车机播放胶囊按键变成“全黑无法看清”的问题。
- **播放队列与播放模式兼容**：自动透传播放器提供的真实歌单列表；支持标准循环模式及主流应用的自定义播放模式透传。
- **行车安全通知伴侣**：智能识别私聊与群聊结构，过滤群聊刷屏，仅保留关键消息，并在车机端生成符合规范的朗读卡片与“标记已读”消除操作。
- **断连防漏音与防颠簸保护**：拔线断开车机或音频物理中断时，立即抢占音频焦点并下发全量暂停，防止手机外放尴尬；切歌时提供状态保护锁，消除切歌过程中的闪烁。
- **极简手机端前端页面**：手机端提供精致的流体控制台，实时呈现音源感知状态与关键通知传递记录，支持深浅色自适应切换、四国语言切换以及系统权限引导。

| :--- | :---: | :--- | :--- |

| **冷启动唤醒** | **完全支持** | 目标未运行时自动在后台唤醒并在就绪后起播 | 依赖手机系统允许应用后台自启动 |
| **消息通知展示** | **完全支持** | 智能解构私聊与群聊，清洗前缀，构建车规级消息卡片 | 依赖用户授予系统通知使用权 |
| **语音朗读** | **系统接管** | 严格遵循车载规范，由车机语音助手自动朗读 | 朗读发音取决于车机系统当前配置的语音包 |
| **消息直接回复** | **不支持** | 仅提供车机端“标记已读”消除通知。**不支持向原应用反向代发消息** | 第三方即时通讯软件未开放外部消息代发接口 |

## 运行要求

- **手机操作系统**：Android 10.0 及以上（系统已内置 Android Auto，插车即用；最低兼容 Android 8.0，需在Play商店额外下载）。
- **车载环境**：支持有线或无线连接的 **Android Auto** 车机，或PC端运行的官方测试套件DHU。
- **应用环境**：手机上已安装常规音频软件或即时通讯软件。

## 安装指引

1. **下载安装包**：前往本仓库右侧的发布页面下载最新版安装包。
2. **安装并授予权限**：
   - 打开应用，按照提示开启**通知使用权**；
   - 允许 Fahrmony **忽略电池优化**，防止系统在熄屏长途驾驶时杀死后台服务；
   - 安卓 13 及以上设备请允许**发送通知**权限。
3. **开启车载开发者设置**：
   - 打开手机系统设置，搜索并进入 `Android Auto`；
   - 滚动到最底部连续点击版本号 10 次开启开发者模式；
   - 点击右上角三个点，进入**开发者设置**，勾选**未知来源**（允许本地插件在车机显示）。
4. **连接车机**：通过数据线或无线投屏连接车辆，车机桌面将自动出现图标，点击即可使用。

## 常见问题解答

#### 每次上车都需要在手机或车机上手动点按播放吗？
绝大多数日常用车场景下完全不需要。Fahrmony 针对车载环境的“冷启动”与“热重连”场景进行了深度专项打磨。多数情况下，当手机通过数据线或无线投屏连接至 Android Auto 时，系统会自动建立会话感知并尝试恢复先前的播放流，无需掏出手机或在车机屏幕上手动翻找点按；即使目标音频 App 在后台已被系统清理挂起，也能在建立连接时自动完成唤醒与续播。

#### 为什么不能在车机屏幕上直接打字或语音回复消息？
主要出于行车安全与技术合规考虑。开车过程中在屏幕上频繁打字极其危险；同时主流通讯软件并未开放第三方的消息发送接口。软件坚持只读原则，不搞逆向破解，保障安全纯净。

#### 为什么车机上显示的专辑背景是流光色彩而不是原图？
部分第三方播放器的原版封面色调极暗，容易导致车载系统把播放控制按键自动变成无法看清的黑色，且大尺寸图片传输易引起卡顿。自适应流光背景能保证按键始终清晰可读，切歌更加流畅。

#### 声音是从汽车音响出还是从手机喇叭出？
连接车机后，声音自动通过汽车音响播放。当断开连接拔掉数据线时，内置的防漏音机制会自动执行静音暂停，防止手机在车外突然大声外放。

## 可能的异常及排除办法

### 1. 车机屏幕没有出现 Fahrmony 图标
- **排查**：手机端设置中未勾选“未知来源”。
- **解决**：进入手机设置 -> Android Auto -> 连点版本号 10 次激活开发者选项 -> 右上角菜单 -> 开发者设置 -> 勾选“未知来源”，然后重新连接。

### 2. 车机显示“等待音乐播放中”或媒体源未列出
- **排查**：手机刚开机或目标音乐软件处于休眠状态，尚未向系统注册媒体会话。
- **解决**：在手机上先手动点开一次常用的音乐软件播放任意声音，或在车机端列表页中直接点击对应音源名称触发唤醒。

### 3. 歌曲名称显示为空或仅显示“正在播放”
- **排查**：部分应用在启动音频解码时向系统发布歌曲信息较为滞后。
- **解决**：应用内置了状态栏信息自动提取机制，稍等片刻即可自动补齐歌名。

### 4. 点击播放有效，但“上一曲”或“下一曲”按键无效
- **排查**：当前播放的音频源（如特定网络电台）本身未实现切换曲目的代码逻辑。
- **解决**：此为原软件对系统媒体接口的实现限制，属于正常现象。

### 5. 车机点击播放后未能唤醒目标播放器
- **排查**：手机系统限制了后台自启动。
- **解决**：进入手机系统应用管理，为 Fahrmony 及常用的音乐软件开启“允许自启动”和“允许关联启动”权限。

### 6. 循环播放或随机播放按键没有反应
- **排查**：目标音乐软件未遵循标准接口向系统开放循环模式控制。
- **解决**：为防止误操作，未开放该接口的软件在车机端将保持默认状态。

### 7. 收到即时消息，车机中控没有弹窗提示或朗读
- **排查**：未开启通知使用权，或在设置中开启了“过滤群聊消息”。
- **解决**：检查手机设置，确保通知使用权和通知发送权限处于正常开启状态。

### 8. 长途行驶一段时间后服务突然中断
- **排查**：手机系统省电策略终止了后台服务。
- **解决**：在手机电池设置中，将应用及常用的音频软件电池策略更改为“无限制”。

## 隐私承诺

1. **完全本地运行**：所有通知读取、文本分析与媒体状态同步，全过程**仅在手机运行内存中即时处理**，用完即焚，绝不保存到存储设备。
2. **无云端服务器**：本项目不架设、不租赁、不连接任何远程网络服务器，零网络数据交换。
3. **无数据统计追踪**：不集成任何商业统计分析、广告推广或异常崩溃收集插件。
4. **随时自主撤销**：通知使用权与系统权限可随时在手机系统设置中一键关闭。

## 架构设计

```text
┌─ 第三方应用 (音乐、播客与即时通讯软件)
│  └─ 媒体会话令牌 (MediaSession) / 系统通知广播
▼
┌─ Fahrmony 独立车载系统进程 (:car)
│  ├─ 媒体会话感知、智能仲裁与冷启动唤起
│  ├─ 消息特征清洗、群聊过滤与规范化转译
│  ├─ 车载媒体浏览服务 (MediaBrowserServiceCompat)
│  └─ 长效前台守护服务
▼
┌─ Fahrmony 手机端前端页面 (主进程)
│  └─ 链路状态监测、通知音源记录与多语言切换
▼
┌─ 车载中控屏幕 (Android Auto)
│  ├─ 屏幕媒体播放控制台与分屏卡片
│  └─ 车载语音助手安全朗读消息通知
```

- **交互与多语言**: Vanilla CSS, Native i18n
